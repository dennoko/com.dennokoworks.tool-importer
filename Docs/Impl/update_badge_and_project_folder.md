# BLM 更新通知アイコン / Project タブで開く導線 要件定義

- 作成日: 2026-11-04
- 更新日: 2026-11-05（2.2 の調査結果を反映し、機能 A の表示条件を確定）
- ステータス: 要件確定

---

## 1. 概要
アイテム一覧に次の 2 機能を追加する。

| # | 機能 | 目的 |
|---|---|---|
| A | **更新ありアイコン** | BOOTH Library Manager (BLM) が商品の更新を検知しているアイテムを一覧上で分かるようにする |
| B | **Project で表示** | インポート済みアイテムのフォルダを Project タブで選択・ハイライトし、導入先をすぐに辿れるようにする |

## 2. 機能 A: 更新ありアイコン

### 2.1 要件
1. BOOTH で新しいファイルが公開されていて、**まだ BLM でダウンロードしていない**アイテムに、**更新ありアイコン**を表示する。
2. 判定には BLM の更新通知（2.2）と、BLM のアイテムフォルダの中身を使う。本ツールは独自の既読・確認済みの状態を持たない。
   - BLM の通知の**既読 / 未読は判定に使わない**。BLM の通知画面で既読にしても、最新版をダウンロードするまではアイコンを出し続ける。
   - BLM で最新版をダウンロードすると、次回の読み込みからアイコンが消える。
   - 本ツールでインポートしても、それだけではアイコンは消えない。
3. 対象は**一覧に表示される全アイテム**とする。
   - 全ショップ（ショップ = None を含む）で表示する。dennokoworks 限定にはしない。
   - インポート状態（未導入 / 一部導入 / 導入済み）に関わらず表示する。
   - `.unitypackage` が無く一覧から除外されているアイテムは、もともと表示されないため対象外。

### 2.2 更新通知の取得元（調査結果）
2026-11-05 に BLM v0.5 系の `data.db`（`schema_version = 20260114`）、ログ、本体を調べた結果。

**通知テーブル**

```sql
CREATE TABLE notifications (
   id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
   title TEXT,
   content TEXT NOT NULL,          -- JSON
   read INTEGER NOT NULL DEFAULT 0,
   created_at TEXT NOT NULL        -- UTC（例: 2026-11-03T10:29:07Z）
)
```

- `content` は次の JSON。`type` は `latestDownloadableAvailable`（ファイル更新）と `downloadFailed`（ダウンロード失敗）の 2 種類で、本機能では `latestDownloadableAvailable` だけを使う。
  ```json
  {"type":"latestDownloadableAvailable","data":[14378106,["Hikari_Win_v2_6_17.zip","Hikari_Mac_v2_6_17.zip"]]}
  ```
  - `data[0]`: **バリエーション ID**（`booth_item_variations.id`）。`booth_items.id` / `registered_items.id` ではない。
  - `data[1]`: BOOTH で新しく公開・更新されたファイル名の一覧（そのバリエーションの全ファイルではなく、変更があったものだけ）。
- 1 アイテムに複数の通知がたまることがある（バージョンが上がるたびに 1 件ずつ増える）。

**アイテムとの紐付け**

`notifications.content` の `data[0]` → `booth_item_variations.id` → `booth_item_variations.booth_item_id` → `registered_items.booth_item_id` → `registered_items.id`（= `BlmItem.RegisteredId`）。BLM 本体の通知画面も同じ経路（`getBoothItemByVariationId`）でアイテムを引いている。`booth_item_variations` に無いバリエーション ID の通知は、BLM 本体でも商品情報を表示できないため無視する。

**通知が消える・変わる条件（BLM 本体の動作）**

| 操作 | DB の変化 |
|---|---|
| 通知画面でカードをクリック / 「すべて既読にする」 | `read` が 1 になる |
| 既読の古い通知 | 新しい通知の登録時に BLM が削除する（`DELETE ... WHERE id <= ? AND read > 0`。基準の ID の決め方は不明） |
| アイテムを BLM から削除 | そのアイテムの通知が削除される |
| BLM で再ダウンロード | **何も変わらない**（通知は残り、既読にもならない） |

このため、既読フラグや通知の有無だけでは「最新版をダウンロード済みか」は分からない。2.2.1 のとおり、アイテムフォルダの中身と照らし合わせて判定する。

**使わないもの**
- `booth_item_update_history`: BLM が次にどのアイテムの情報を BOOTH から取り直すかを決める順番表（`last_updated_at` の古い順に 1 件ずつ取得し直す）。全アイテムに行があり、更新の有無とは関係ない。
- `booth_items.updated_at`: 名前・説明文・タグの変更でも更新されるため、ファイル更新の判定には使えない。

**古い BLM**: `notifications` または `booth_item_variations` テーブルが無い場合は、更新ありアイテムなし（空集合）として扱う。

#### 2.2.1 「更新あり」の判定
1. `notifications` から `type` が `latestDownloadableAvailable` の通知をすべて読む（**既読も含める**）。
2. アイテムの**バリエーションごとに最新の通知**（`id` が最大のもの）を 1 件選ぶ。
3. その通知の `data[1]` のファイルが、BLM のアイテムフォルダ（`BlmItem.ItemDirectory` の直下）に**1 つも無い**場合、そのバリエーションは「未ダウンロード」とする。
   - BLM は zip を、拡張子を除いた名前のフォルダに展開する（例: `mask_maker_v4.1.1.zip` → `mask_maker_v4.1.1\`）。zip 以外はそのままのファイル名で保存する。
   - そのため、ファイル名 `f` について「`f` という名前のファイルがある」または「`f` が `.zip` で終わり、拡張子を除いた名前のフォルダがある」ときに、ダウンロード済みとみなす。比較は大文字・小文字を区別しない。
   - 1 つでもあればダウンロード済みとする（すべては求めない）。Win 版 / Mac 版や、本体 / PSD のように、必要なファイルだけをダウンロードする使い方があるため。
4. 「未ダウンロード」のバリエーションが 1 つでもあるアイテムを「更新あり」とする。
5. アイテムフォルダが無い（BLM の保存先が見つからない等）場合は「更新あり」とする。

参考（調査時の DB）: 登録アイテム 628 件のうち、通知があるのは 168 件、上記の判定で「更新あり」になるのは 153 件。

**既知の制限**
- ダウンロード後にユーザーが BLM のアイテムフォルダからそのファイル / フォルダを削除・リネームすると、再び「更新あり」になる。
- BLM がファイル名を変えて保存した場合（OS で使えない文字の置換など）は、ダウンロード済みと判定できず「更新あり」のままになる可能性がある。

#### 2.2.2 実装方針
- `BlmDataAccessor` に、更新ありの判定に必要な情報（登録アイテム ID → バリエーションごとの最新通知のファイル名一覧・通知日時・バリエーション名）を返すメソッドを追加する。既存の `GetLists` と同様に、テーブルが無ければ空を返し、エラーにはしない。
  - 取得 SQL の例（JSON の解析は C# 側で行う）:
    ```sql
    SELECT id, content, created_at FROM notifications
    WHERE content LIKE '%"latestDownloadableAvailable"%'
    ORDER BY id DESC;

    SELECT v.id, v.variation_name, r.id
    FROM booth_item_variations v
    JOIN registered_items r ON r.booth_item_id = v.booth_item_id;
    ```
  - `content` の解析に SQLite の `json_extract` は使わない。使用する `winsqlite3` / macOS の `libsqlite3` のバージョンによっては JSON 関数が無いため、正規表現（`"data":\[(\d+),\[(.*)\]\]`）などで C# 側で取り出す。
- フォルダの中身の確認（2.2.1 の 3）は、DB の読み込みとは別に、アイテムごとに `Directory.Exists` / `File.Exists` で行う。
- DB は既存と同じく読み取り専用で開く（ロックされていれば一時コピーから読む）。BLM の DB には書き込まない。
- 読み込みはアイテム一覧の再読み込み（`Reload`）と同じタイミングで行う。ウィンドウ表示時・「一覧を再読み込み」・ショップ切り替え時が該当し、定期的な監視はしない。
- 結果は `ToolItemState` に、更新ありの bool と、ツールチップ用の情報（最新の通知日時・ファイル名・バリエーション名）として持たせる。

### 2.3 表示仕様
- **位置**: アイテム名（`item-title`）の左に小アイコンを置く。タイトルと同じ行に並べる。
- **アイコン**: Unity 組み込みアイコン（`EditorGUIUtility.IconContent`）を使い、新しい画像アセットは追加しない。具体的なアイコンは実装時に選ぶ。dennokoworks のバージョン確認で使う警告色とは見分けがつくものにする。
- **ツールチップ**: 「BOOTH でこのアイテムのファイルが更新されています。BLM で最新版をダウンロードしてください。」に相当する文言に、次の情報を併記する。
  - 通知日時（`created_at` をローカル時刻に変換）
  - 新しいファイル名（`data[1]`）。バリエーション名があれば「バリエーション名: ファイル名, ...」の形にする。
  - 未ダウンロードのバリエーションが複数ある場合は、バリエーションごとに 1 行ずつ並べる。
- **クリック時の動作**: なし（表示のみ）。BOOTH への導線は既存の [BOOTH] ボタンを使う。
- **ローカライズ**: 文言は `ToolImporterLoc` に日本語・英語を追加する。

### 2.4 既存機能との関係
- **dennokoworks のバージョン確認**（GitHub の version.json との比較、`item-version-box`）とは独立している。両方の条件を満たすアイテムには、両方を表示してよい。
- **絞り込み**: 「更新あり」でのフィルターは今回作らない。
- **「更新ありを選択」ボタン**（複数選択モード）: BLM の更新通知は対象に含めない。既存どおり dennokoworks 限定で、BLM 内のパッケージがローカルより新しいものだけを選ぶ。
  - 理由: 更新ありアイコンは「BLM に新しい版がまだダウンロードされていない」状態を表すため、そのままインポートしても古い版が入るだけになる。

## 3. 機能 B: Project で表示

### 3.1 ボタン
- **位置**: アイテム行の左側のボタン群で、既存の [BOOTH] [フォルダ] の後ろに **[Project]** を追加する。
  - 既存の [フォルダ] は BLM のアイテムフォルダをエクスプローラー / Finder で開くボタンなので、それとの違いが分かるラベルとツールチップにする（例: 「プロジェクト内のインポート先を Project タブで表示」）。
- **有効条件**: 導入状態が `Installed` または `PartiallyInstalled` のときだけ有効にする。それ以外（`NotInstalled` / `Scanning` / `Unknown` / `NoPackage`）は表示したまま無効化する。
- 「その他の導入済みツール」の行には、すでに version.json を Ping するボタンがあるため追加しない。

### 3.2 開くフォルダの決定ルール
クリックのたびに次の手順で求める（事前計算・キャッシュはしない）。

1. 導入判定と同じく、**最新パッケージ**の解析結果（`PackageScanResult.guids`）を使う。
2. 各 GUID を `AssetDatabase.GUIDToAssetPath` でパスに変換し、プロジェクト内に存在するものだけを残す。
   - GUID で引くので、インポート後にユーザーがフォルダを移動・リネームしていても現在の場所を追える。
3. フォルダ（`AssetDatabase.IsValidFolder`）を除き、**実ファイルだけ**を残す。
   - 実ファイルが 1 つも無く、フォルダだけ残っている場合は、フォルダのパスを使って同じ手順を続ける。
4. 残ったパスの**共通の親フォルダ**を求める。
   - 例: `Assets/shop/item/hoge.prefab` だけなら → `Assets/shop/item`
   - 例: `Assets/shop/item/Prefabs/a.prefab` と `Assets/shop/item/Materials/b.mat` → `Assets/shop/item`
5. 共通の親がルート（`Assets` または `Packages`）より深ければ、そのフォルダを開く。
6. 共通の親がルートそのもの（Assets 直下に複数のフォルダが作られている等）になる場合は、**ルート直下のフォルダごとにグループ分けし、各グループの共通の親を候補**にしてメニュー（`GenericMenu`）を出す。
   - 例: `Assets/ToolA/Prefabs/x.prefab` と `Assets/Plugins/ToolA/y.dll` → 候補は `Assets/ToolA/Prefabs` と `Assets/Plugins/ToolA`
   - ルート直下に直接置かれたファイルは、`Assets`（`Packages`）という 1 つの候補にまとめる。
   - 各候補には、含まれるアセット（実ファイル）の数を付ける。並び順はアセット数の多い順とする。
   - `GenericMenu` は `/` をサブメニューの区切りとして扱うため、既存のリストメニューと同じく表示上は全角の `／` に置き換える。
   - グループ分けの結果、候補が 1 つになった場合はメニューを出さずにそのまま開く。

### 3.3 開き方
- 対象フォルダを `Selection.activeObject` に設定し、`EditorGUIUtility.PingObject` でハイライトする。Project ウィンドウは `EditorUtility.FocusProjectWindow` で前面に出す。
- 公開 API だけで実現する。2 カラム表示で右ペインにフォルダの中身を出すこと（内部 API `ProjectBrowser` のリフレクション）はしない。

### 3.4 エッジケース
| ケース | 挙動 |
|---|---|
| ボタンを押すまでの間にアセットが削除され、手順 2 で何も残らない | ボタン押下時に何もせず、ステータスに「プロジェクト内にインポート済みのアセットが見つかりません」を表示し、状態を再計算する |
| パッケージ解析が無効（`scan.IsValid == false`） | 導入状態が `Unknown` のためボタンは無効 |
| 古い版のパッケージだけがインポートされている（最新版とアセット構成が違う） | 最新パッケージと共通の GUID だけで判定する（導入判定と同じ基準）。GUID が 1 つも重ならなければ `NotInstalled` になりボタンは無効 |

## 4. 今回の対象外
- 「更新あり」による絞り込み（フィルター）
- 本ツール側での更新通知の既読・確認済み管理
- アイコンをクリックしたときの動作（BOOTH / BLM を開く等）
- BLM を外部から起動し、該当アイテムを開く導線
- Project ウィンドウの 2 カラム表示で、フォルダの中身を右ペインに直接表示すること

## 5. 検証項目
※ 実装時の確認はコンパイル（構文）チェックのみ。Unity 上の動作確認は作者が実施する。

### 機能 A
1. BLM に更新通知があり、最新版を未ダウンロードのアイテムだけに、タイトル左のアイコンが表示されること（全ショップ / ショップ = None / 未導入アイテムを含む）
2. BLM の通知画面で既読にしても、アイコンが消えないこと
3. BLM で最新版をダウンロードし、「一覧を再読み込み」するとアイコンが消えること
4. 通知のファイルのうち一部（例: Win 版だけ）をダウンロードした場合もアイコンが消えること
5. 本ツールでインポートしただけではアイコンが消えないこと
6. `notifications` / `booth_item_variations` テーブルの無い古い BLM の DB でも、エラーにならず一覧が表示されること
7. ツールチップに通知日時・ファイル名（バリエーション名）が表示され、日本語 / 英語の切り替えで文言が切り替わること

### 機能 B
1. `Assets/shop/item/...` に入るパッケージで `Assets/shop/item` が選択・ハイライトされること
2. Assets 直下に複数のフォルダを作るパッケージで候補メニューが出て、選んだフォルダが開くこと
3. インポート後にフォルダを移動しても、移動先が開くこと
4. 未導入のアイテムではボタンが無効になっていること
5. Project ウィンドウが 1 カラム / 2 カラム表示のどちらでも動くこと
